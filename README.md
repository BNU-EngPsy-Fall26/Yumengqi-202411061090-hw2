## 任务概览

三个经典实验**跨越 W6–W8、三种不同范式**，每个都 = 经典复现 + 一个改进条件，对应课程问题链「找得到吗 → 看得懂吗 → 知道自己在哪吗」：

| 实验 | 周次 / 范式 | 复现 | 改进条件 | 理论依据 | 预测 |
|---|---|---|---|---|---|
| 视觉搜索 | W6 / 搜索斜率 RT | 特征 vs 联合（Treisman & Gelade, 1980） | **搜索不对称**：找 Q（有特征）vs 找 O（缺特征） | 特征整合论 FIT（Treisman & Souther, 1985） | 找 Q 斜率≈0 < 找 O |
| Cleveland–McGill | W7 / 图形估计误差 | 位置 / 长度 / 角度 / 面积 编码排序（Cleveland & McGill, 1984） | **3D 饼图失真**（透视把角度压扁） | 图形知觉、兼容性 | 位置 < 长度 < 角度 < 面积，且 3D 角度 > 角度 |
| FORT 地图 | W8 / 空间旋转 RT | 北向上 vs 航向上（Aretz, 1991） | **让车动起来**（运动提供光流、更新航向） | 参照系变换 FORT、光流/直接知觉（Gibson） | 静止时航向上 < 北向上；运动缩小北向上的旋转代价 |

## 每个实验的设计

### 1. 视觉搜索（W6）
- **出处**：Treisman & Gelade (1980) *A feature-integration theory of attention*；不对称见 Treisman & Souther (1985)。
- **自变量**：搜索类型（特征 / 联合）× 集合大小 N（4/8/16/24）× 目标有无（各 50%）；改进段 = 搜索不对称（找 O / 找 Q，同色字母，N 4/8/16）。
- **因变量**：RT、正确率；核心效应 = **RT ~ N 的斜率**。
- **特征搜索**：目标红 O，干扰蓝 O + 蓝 X；**联合搜索**：目标红 O，干扰红 X + 蓝 O（必须绑定颜色×形状）；**不对称**：Q 比 O 多一条小尾巴，找「有特征 Q」vs「缺特征 O」。
- **按键**：有 F / 无 J。试次：24（特征）+ 24（联合）+ 24（不对称）= 72 次 + 练习。
- **预测**：找 Q（特征出现）跳出、斜率≈0；找 O（特征缺失）逐个搜、斜率更大。

### 2. Cleveland–McGill（W7）
- **出处**：Cleveland & McGill (1984) *Graphical perception*；Heer & Bostock (2010) 复刻比例。
- **自变量**：编码方式 5 水平——位置（共同轴）/ 长度（浮动条）/ 角度（饼图）/ 面积（气泡）/ **角度 3D（改进）**。
- **因变量**：估计误差 = |估计百分比 − 真值|（越小越准），另记 RT。
- **任务**：每屏 5 个图形，标 A、B 两个（A 较大），估计「B 是 A 的百分之几」（输入 0–100）。
- **试次**：5 编码 × 5 比例 × 2 重复 = 50 次 + 练习 2 次。
- **预测**：位置 < 长度 < 角度 < 面积（Cleveland–McGill 排序）；3D 饼图因透视压扁角度、估计更差。

### 3. FORT 地图（W8）
- **出处**：Aretz (1991) *The design of electronic map displays*；Aretz & Wickens (1992) 参照系变换 FORT；Gibson 光流/直接知觉。
- **自变量**：2 × 2 被试内——地图朝向（北向上 / 航向上）× 运动（静止 / 运动）。
- **因变量**：RT、正确率（判断「下一个路口，目的地在车的左边还是右边」，←/→）。
- **任务**：小地图上蓝箭头 = 车、红点 = 目的地；北向上时地图固定、车箭头朝各航向，需心理旋转；「运动」条件下车会一路开向路口（光流）。
- **试次**：4 条件 × 12 = 48 次 + 练习，4 个 block 顺序随机。
- **预测**：静止时航向上 < 北向上（复现 Aretz）；运动提供光流、持续更新航向，缩小北向上的旋转代价（北向上·运动 < 北向上·静止）。

## 数据分析要点（评分 30 分）

- **每实验 ≥ 5 名他人**：在 `/hw2`「我的项目」看人数，或网页「全体被试」区自动统计。
- **每条件 ≥ 10 试次**：搜索每格 3/2 次 × 多 N 合计 ≥ 12；CM 每编码 10 次；FORT 每条件 12 次。均满足。
- **效应计算**：搜索算 RT~N 斜率；CM 算平均估计误差；FORT 算正确 RT + 正确率。
- **与原文对比**：搜索段内置 Treisman & Gelade (1980) 原文斜率（特征 有 3.1/无 25.1；联合 有 28.7/无 67.1 ms/项）。
- **检验改进条件**：对比「找 Q vs 找 O」「3D vs 2D 角度」「静止 vs 运动（FORT）」，看是否支持预测。

## 提交数据格式（已按接口要求实现）

- `POST /api/hw2/submit`，body：`{ project, experiment, participant, trials, meta }`。
- 实验名：`search` / `cm` / `fort`（小写）；调试时把 `TEST_MODE` 设为 `true` 会加 `test_` 前缀，正式收数前改回并清空测试数据。
- 每试次是扁平对象，值只用数字 / 字符串 / 布尔，**不含 null、数组、对象**（超时 `rt=0` + `timeout=1`，分析过滤 `rt>0`）。
- 网页内已 `try/catch` 提交结果并显示后台 `warnings`；失败提示「数据未上传」。

## 眼动说明（WebGazer）

- 点击首页「同意并开始（含眼动校准）」会依次：知情同意（含年龄/性别）→ 开启摄像头（画面隐藏、不上传）→ **9 点校准**（盯住+点击）→ **3 点验证并汇报误差** → 每个试次记录注视坐标（字段 `samples`，为 `[x1,y1,x2,y2,…]` 扁平数字数组，≤500 项，屏幕像素）。
- **摄像头需要安全上下文**：双击 `file://` 通常打不开摄像头，此时自动回退到「鼠标模式」（只记按键，数据照常提交）。要真正启用眼动，用**本地服务器**打开（`python -m http.server` 后访问 `http://localhost:8000`；localhost 是安全上下文），或用 https（如 GitHub Pages）。
- 视频只在本地浏览器处理、**绝不上传**；只上传注视坐标。结果页会画一张你本人的**注视热力图**（视觉搜索段）。
- WebGazer 精度有限（约 4°），因此更适合「注视落在哪个大区域」这类分析，而非精确到像素。
- **被试在别的设备上**：鼠标模式直接把 `index.html` 发给对方即可（对方双击打开、数据照常上传，无需服务器）；要做眼动，则每个被试需用自己的摄像头 + 页面必须是 https（公开托管，如 GitHub Pages、Netlify Drop）。
